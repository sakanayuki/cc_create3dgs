# 09. 斜めから見たときの破綻と、その検査

単一の写真から作る 3DGS は、**正面から見るぶんには写真そのもの**である。前面シェルは写真の画素をその深度に置いただけなので、正面図が元の写真と一致するのは当たり前で、そこを見ても品質は分からない。

実際に壊れているかどうかは、**少し回して初めて分かる**。ここは実写で見つかった壊れ方を型として整理し、それぞれをどう検査するかを決めたものである。

## 9.1 見つかった壊れ方

実写（プールサイドの人物、1116×2000）の出力 `.splat` を解析して見つけたもの。

### V1 輪郭の膜（silhouette membrane）

**症状。** 正面からは見えないが、20°ほど回すと**体の後ろへ平らな板が伸びる**。色は被写体の縁の色なので、肌色や服の色をした「羽根」に見える。

**原因。** 単眼深度モデルは物体の縁で前景と背景を混ぜた値を返す。にじみは α の軟化部分だけでなく、**α が 1 の内側にも数画素続く**。モデルは 518² で推論して 1024² へ引き伸ばすので、そのぶん帯も広がる。

実測（シルエットからの距離ごとの、深度が最奥に張り付いた画素の割合）:

| 距離 | 1px | 2px | 4px | 6px | 8px | 12px |
|---|---|---|---|---|---|---|
| 最奥に張り付き | 56% | 45% | 28% | 14% | 6.6% | 3.0% |

被写体の 6.9% がこれだった。輪郭に沿って最奥へ張り付いたサーフェルが一枚の膜を作る。

**対策。** `pullBoundaryDepthInward` に `coreDistance` を持たせ、シルエットから一定距離以内の画素を、それより内側の「芯」の深度で置き換える。作業グリッドの 0.8%（1024² なら 8px）。1px の縁の張り付きが 56% → 7.2% に落ちる。

**検査。** `tests/unit/viewSanity.test.ts`。凸な体は回すと見かけの面積が**少し減る**。膜があると逆に**増える**（膜が横を向いて広がるため）。実測で 1.15 倍 → 0.89 倍。点群の奥行き幅でも見る（0.224 → 0.358 → 0.234）。

### V2 詰め物が呼ぶマットの誤検出（letterbox bleed）

**症状。** 被写体でないもの（プールサイド、荷物）が被写体に含まれ、斜めから見ると**大きな平らな板**として突き出す。

**原因。** ⓪ 前処理はアスペクト比を保つためレターボックスで正方形にする。その詰め物を**黒のまま**モデルへ渡していた。内容の縁に強い段差ができ、MODNet がそこに反応する。

実測（y=900 の行で被写体とされた x の区間。人物の腕は x≈314 から）:

| マットへの入力 | 区間 |
|---|---|
| 黒帯つき（旧） | **226**..385, 407..501, 524..690 |
| 端の画素で埋める（新） | **312**..385, 410..691 |
| 詰め物なし | **312**..690 |

黒帯があると 88 画素ぶんのプールサイドを被写体に含めていた。**被写体の内部にも穴**（386-406, 502-523）ができていた。

副作用として深度モデルの内部パラメータも歪んでいた。焦点距離の推定が 891px → 1133px と変わる。

**対策。** `replicateEdgesIntoPadding`。詰め物の RGB を内容の端の画素で埋める。**α は 0 のまま**残す（後段が「ここに被写体は無い」と判別する意味は変えない）。

**検査。** `tests/unit/preprocess.test.ts`。詰め物の RGB が端の色になること、α が 0 のままであること、縁に段差が残らないこと。

### V3 スカートの誤爆（skirt storm）

docs/03 §3.5.5 に詳細。深度の段差判定が固定閾値だったため、普通の顔の傾斜が「不連続」と判定され、スカートが顔じゅうに林立した（全スプラットの 63%）。顔が縦に割れて見える。

**検査。** `tests/unit/splatBuild.test.ts`。勾配が大きくなってもスカートの割合が暴走しないこと。

### V4 奥行きの伸びすぎ（stretched depth）

**症状。** 20°ほど回すと体が奥行き方向の筋に散り、45°では原形をとどめない。正面からは完全に正常に見える。

**原因。** 被写体が視線方向に約 2 倍伸びていた。他実装の理想的な出力と比べると:

| 上から見た輪切りの 奥行き ÷ 幅 | 理想 | photosplat（修正前） |
|---|---|---|
| 頭 | 0.69 | 2.25 |
| 胸 | 0.77 | 1.76 |
| 腰 | 0.91 | 2.14 |
| 全体 | **0.895** | **1.899** |

輪切りで見ると、理想はなめらかな一枚の弧、こちらは引き裂かれた多層になる。

**先に潰した仮説（いずれも主因ではなかった）。** スプラットの大きさ・形（理想並みに小さくしても変化なし）、背面シェルとスカート（前面だけにしても残る）、深度の急な段差（除いても 0.806 → 0.782 にしかならない）。決定打は、**出力の z を 0.45 倍するだけで 45° まで破綻が消えた**こと。

**内訳。**

| 構成 | 奥行き ÷ 身長 |
|---|---|
| 理想 | 0.356 |
| DA3 の実寸のみ | 0.506 |
| ＋局所強調 ×3 | 0.666 |
| ＋タイル融合 | 0.760 |
| 両方（修正前） | **0.837** |

**対策 3 つ。**

1. **タイルは細部だけを担当させる**（`FuseParams.detailScalePx = 16`）。タイルは全体パスと違う切り出し方で推論されるので低周波が一致しない。ラプラシアンの粗い層を全体パスに固定した。奥行きが 0.837 → 0.721 に下がり、**同時に顔の起伏が 87.8 → 183.2 と 2.1 倍**になった。低周波の食い違いが細部を潰していた。
2. **局所強調で奥行き幅を広げない**。「大域の形は平滑化成分が持つので比率は変わらない」と書いていたが実際は +34% 広がっていた。強調後に元の幅へ戻す。局所の起伏も同率で縮むが、**まわりに対する比**は上がったままで、欲しいのはそちらである。
3. **妥当性は高さでなく幅で見る**（`PLAUSIBLE_DEPTH_TO_WIDTH = 0.40〜0.85`）。奥行き ÷ 高さは構図で大きく変わる（全身 0.36 / バストアップは 1 に近い）が、人はどこを切っても幅と同じくらいの奥行きを持つ。あわせて背面シェルの厚みを 0.35 → 0.12 にした（前後の隔たり 0.127 → 0.051、理想は 0.012）。

**結果。** 奥行き ÷ 幅 1.899 → **0.872**（理想 0.895）。20°/40° とも人物として成立する。

**検査。** `tests/unit/viewSanity.test.ts` の `depthToWidth`。この破綻は連結性でも穴率でも捕まらなかったので、指標を足した。

### V5 層の分離（残課題）

**症状。** 30°を超えると、体が奥行き方向に離れた板の重なりに見えてくる。45°では頭部が胴から浮いて見える。

**原因。** 未特定。単一視点からは側面の情報が無いこと自体が原理的な限界でもあるので、どこまでが直せる欠陥かの切り分けが要る。

**現状の扱い。** V4 の修正で 40° まで大きく改善した。残るのは細かな層感で、単一視点の原理的な限界との切り分けが要る。

## 9.2 検査の考え方

正面図の一致だけを見ても意味が無い（前面シェルは定義上一致する）。**回して測る**。

`tests/helpers/splatView.ts` が最小の描画器を持つ。α はほぼ 1 なので z バッファで十分に近似できる。見た目の美しさは測らず、次の 4 つだけを見る。

| 指標 | 何を捕まえるか | 目安 |
|---|---|---|
| 最大連結成分の割合 | 体が断片に割れていないか | > 0.97 |
| シルエット内側の穴率 | 面が抜けていないか | < 0.1 |
| 回したときの面積比 | 輪郭の膜（V1） | < 1.0 |
| 点群の奥行き幅 | 輪郭の膜（V1） | 実形状の 1.15 倍以内 |

実写での前後比較（描画 260×380、被写体の連結性と穴率）:

| | yaw 0 | yaw 15 | yaw 30 | yaw 45 |
|---|---|---|---|---|
| 修正前 断片数 | 2 | 1 | 2 | 2 |
| 修正後 断片数 | **1** | **1** | **1** | **1** |
| 修正前 穴率 | 21.3% | 19.4% | 8.6% | 8.4% |
| 修正後 穴率 | **17.7%** | **10.4%** | **6.3%** | **4.7%** |

## 9.3 手順の落とし穴（自分が踏んだもの）

**ワールド z の向き。** `6-splats.ts` の `toWorld` は y と z を反転する。ワールド z は**大きいほど手前**である。逆に取ると背面シェル（`backShade` で 0.55 に減光されている）越しに見ることになり、「全体が暗く濁って壊れている」ように見える。実際には前面シェルは正常だった。検査用の描画器を書くときはここを確かめること。

**後処理を飛ばさない。** マットは `refineMatte`（ガイデッドフィルタ → 小島除去 → 穴埋め → 軟化）を通したものが本番の入力である。生の MODNet 出力で調べると、本番には無い穴を「不具合」と見誤る。
