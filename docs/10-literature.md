# 10. 参照実装との比較と、取り込みの判断

単一画像からの 3DGS 生成で先行する 2 つを読み直し、私たちの品質を上げるために
取り込めるものを選別した記録である。**読んだ結果ではなく、実測して採否を決めた
結果**を残す。試して外したものも、再挑戦しないために理由と数字を書く。

| | |
|---|---|
| **SHARP** | [Sharp Monocular View Synthesis in Less Than a Second](https://arxiv.org/abs/2512.10685)（Mescheder ら、Apple、arXiv 2512.10685）。**非商用ライセンスなので、思想のみ参照する。コードも重みも使わない。** |
| **TripoSplat** | [Generative 3D Gaussians with Learned Density Control](https://arxiv.org/abs/2605.16355)（VAST-AI / TripoAI、arXiv 2605.16355、MIT） |

あわせて、手元にある SHARP の出力 `.splat`（513,844 枚）を実測した。論文に書かれて
いない実装の癖は、出力を測るのが早い。

## 10.1 SHARP の構造

Depth Pro のエンコーダ（ViT ×2）＋ DPT デコーダで、**2 層の深度マップ**を出す。
第 1 層が見えている面、第 2 層が遮蔽された領域。そこからガウシアンのパラメータ
（位置・スケール・回転・色・不透明度の 14 個）を 1 パスで回帰する。
1536² 入力 → 768² グリッド × 2 層 ≈ 118 万ガウシアン（入力画素あたり 0.5 個）。

正則化が 3 つある。

- 第 2 層の全変動（TV）平滑化
- **視差勾配による floater 抑制** `L_grad`: 視差の勾配が大きい場所のガウシアンの α にペナルティ
- **射影後のσの上下限** `L_splat`: 画面上のσを [10⁻¹, 10²] に拘束

## 10.2 出力の実測（SHARP 対 私たち）

| | SHARP | 私たち（v2.6.2） |
|---|---|---|
| 枚数 / ファイル | 513,844 / **16.4 MB 無圧縮** | 351,044 / 11.2 MB |
| α の分布 | 中央 251、**α<128 が 5.1%**、255 は 0 個 | 中央 255、**255 が 85.5%** |
| 小軸 ÷ 大軸（厚み） | **0.33〜0.45（大きさ帯によらず一定）** | 0.34（定数の厚みなので大きいものほど平たい） |
| 中軸 ÷ 大軸（面内の異方性） | 0.64〜0.83 | **1.00（真円に固定）** |
| 512² セルあたりの枚数 | **4.78** | 2.38 |
| 背景 | 込み（シーン全体） | 除去済み（被写体のみ） |

## 10.3 取り込みの判断

| | 内容 | 判断 | 根拠 |
|---|---|---|---|
| **P1** | サーフェルに厚みを持たせ、シェーダが使う | **採用（v2.6.3）** | 射影後の細長さ 99% が 6.89 → 3.13。docs/06 §6.11、docs/09 §V15 |
| **P2** | 不透明度を大きさで落とす | **外した** | 実測で悪化（透け 0.69% → 14.75%）。docs/09 §V16(b) |
| **P3** | 面内の異方性 | 保留 | 効果は見込めるが P1 より小さい |
| **P4** | 第 2 深度層（遮蔽領域） | 保留（次の候補） | スカートの原理的な置き換え。質感の差（1 か所あたり 4.78 枚 対 2.38 枚）もここで埋まる |
| **P5** | 視差勾配による floater 抑制 | **目的は達成、手段は別（v2.6.4／6.6）** | 輪郭の行き過ぎは α を落とさず深度を戻して消せた（−18.7mm → −0.4mm、docs/09 §V19）。服の縁（内部エッジ）は**勾配では見つからない**（頂きの勾配が小さい）ので、**細部の振幅の上限**で詰めた。起伏 99% が 9.11% → 5.30%。docs/09 §V21 |
| **P6** | 画面上のσの上限 | **外した** | 上限が一度も効かない。docs/09 §V16(c) |
| **P7** | 予算駆動の適応密度（TripoSplat） | 保留 | ⑦の目標を統合率から枚数へ変える案 |

### 採れないもの（規模）

| | 実際の大きさ | 私たちの予算 |
|---|---|---|
| Depth Pro（SHARP のバックボーン） | 最小の量子化版で **600 MB**（[onnx-community/DepthPro-ONNX](https://huggingface.co/onnx-community/DepthPro-ONNX) の q4f16） | 45.5 MB（人物モード初回） |
| SHARP 全体 | ViT ×2（各 ~326M）＋ DPT ~20M | — |
| TripoSplat | 4.46 GB ＋ 拡散 20 ステップ | — |

**SHARP のシャープさの相当部分は Depth Pro 由来**で、そこは 12 倍以上の予算超過に
なる。学習を要するもの（深度調整 U-Net、SSFT の 2 段目）も、教師付きの視点ペアが
必要なので現状の設計では届かない。

## 10.4 私たちのほうが優れているところ

1. **完全オンデバイス。** モデル 45.5 MB。Depth Pro 単体の 1/13、TripoSplat の 1/100。サーバ不要。
2. **被写体の切り出し。** SHARP はシーン全体を再構成する（出力にも背景が入っている）。人物を素材として取り出す用途では私たちのほうが直接使える。
3. **内容に応じた密度。** SHARP はグリッド 1 マスあたり 2 個の固定で、平らな背景にも同じ密度を割く。私たちは深度・色の分散で統合する。
4. **圧縮。** SHARP の `.splat` は 514k 枚で 16.4 MB 無圧縮。`.pgs` は 750 KB を狙う（※アプリへの配線は未了なので、現時点では設計上の優位）。
5. **検査できる幾何。** 段ごとに分かれた純粋関数と、破綻の型と実測値のカタログ（docs/09）。学習済みモデルはこの直し方ができない。
6. **顔の landmark 事前分布。** SHARP に顔専用の扱いは無い（もっとも、これは深度モデルが弱いことの埋め合わせでもある）。
7. **出力にライセンスの縛りが無い。**
